# TUF-E 项目工作协议 v1.0

> 生效日期: 2026-10-18
> 适用对象: Jayson (决策者) + AI 助手 (执行者)
> 理论基础: TUF-E 公理 3 (跨观察者共识) + 公理 5' (有限截断)

---

## 核心原则

我们双方都是有限观察者。协议的目的不是消除局限，而是**让局限可见、可追踪、可审计**。

---

## R1: 预注册

每次实验前，AI 必须先写预注册文件到 `poc/preregister/` 目录，包含：

```yaml
experiment_id: EXP-XXX
date: YYYY-MM-DD
hypothesis: "具体、可证伪的命题"
success_criteria: "量化判据，不含模糊词"
failure_criteria: "什么结果算推翻假设"
parameters_frozen: [列出所有不可调参数]
analysis_plan: "数据分析方法，不允许事后更改"
```

**预注册文件写入后，方可运行实验。** 实验代码中必须引用预注册 ID。

违反此规则的实验结果标记为 `EXPLORATORY`，不作为正式证据。

---

## R2: 反方论证义务

每个正面结论必须附带以下结构：

```
【结论】: ...
【支撑证据】: ...
【反方论证】: 这个结论可能是错的，因为...
  - 替代解释 1: ...
  - 替代解释 2: ...
  - 当前实验无法排除的反驳: ...
【置信度自评】: HIGH / MEDIUM / LOW + 理由
```

缺少反方论证的结论视为不完整，不得进入正式文档。

---

## R3: 参数冻结

已通过实验的参数不得为了改善结果而调整。

如果确实需要修改参数（例如发现 bug 或设计缺陷），必须：
1. 明确声明"这是参数变更，不是同一实验"
2. 创建新的预注册（新 EXP-ID）
3. 在新预注册中说明为什么旧参数不合适
4. 旧结果保留原样，不被覆盖

---

## R4: 关键决策点暂停

以下情况 AI 必须暂停并等待 Jayson 确认：
- 理论框架的重大变更（新增/删除/修改公理或约束）
- 实验结果的解读分歧
- 是否将探索性结果升级为正式证据
- 项目方向的战略性选择

暂停时 AI 提供选项 + 各选项的利弊分析，不做推荐。决策权归 Jayson。

---

## R5: 不确定性处理（当 Jayson 判断不出走向时）

### R5.1 不要求 Jayson 做超出其判断力的决策

当 Jayson 表示"我不确定"或"我判断不了"时，AI 不得催促或暗示"你应该知道"。

### R5.2 将不确定性转化为可执行的验证步骤

AI 的职责是将"我不知道哪个对"转化为"我们可以做什么来缩小范围"：

```
不确定问题 → 分解为 2-3 个可检验的子命题 → 每个子命题有明确的验证方法
```

示例：
- ❌ "你觉得 PH 检测够好吗？" （要求 Jayson 做技术判断）
- ✅ "PH 检测在以下三种条件下可能失效：(a) 键权重与噪声重叠 (b) 社区数>5 (c) 图密度>0.3。建议分别测试这三种条件，结果会告诉我们边界在哪。"

### R5.3 默认保守策略

当双方都无法判断时，采用以下默认策略：

| 场景 | 默认策略 | 理由 |
|------|---------|------|
| 不确定结果是否可靠 | 标记为 EXPLORATORY，继续收集证据 | C3: 未达共识的知识保留但不用于决策 |
| 不确定两个方向哪个更好 | 都做小规模测试，用数据决定 | C4: 多通道覆盖优先于单通道深度 |
| 不确定某个约束是否过严 | 保持约束，记录不适用的案例 | C5: 宁可过度保护，不可静默丢失 |
| 不确定是否需要新工具/理论 | 先用现有工具做到极限，再引入新依赖 | P2: 保留信息优于引入复杂度 |

### R5.4 外部观察者的引入时机

当内部讨论陷入僵局（连续 2 轮对话无进展）时，AI 应建议引入外部观察者：

- **轻量级**: 用不同 prompt 让另一个 AI 实例独立评估同一问题
- **中量级**: 在 GitHub issue 中公开问题，邀请社区反馈
- **重量级**: 寻找领域专家审阅（Jayson 决定何时值得）

引入外部观察者不是承认失败，是 C3 的正常操作。

---

## R6: 审计日志

所有实验结果、决策记录、参数变更记录保存在 `poc/audit/` 目录。
文件名格式: `YYYY-MM-DD_EXP-ID_description.md`

审计日志不可删除、不可覆盖。只可追加修正说明。

---

## 协议本身的修改

本协议可由 Jayson 随时修改。AI 可建议修改但不得自行执行。
每次修改记录在 `poc/audit/` 中。
